# Graph と Tree の Hybrid 手法の説明

Graphで候補ページを絞り、そのページが属する章をTreeから引いて、章内の位置と前後ページを補う。Graphが「関連ページへの入口」を見つけ、Treeが「その説明の前後関係」を補う狙い。

1. Graphで入口を取る
  - search_graph(query)を実行
  - seedsとexpandedから上位のページを選択
  - Graph候補を3〜5ページ程度に絞る
    - 候補にはページID、章名、ページ番号、Graph上の経路を含む
2. ページIDからTree上の親章を特定する
  - Treeを一度たどり、ページIDから「親章ノード」と「その章内でのページ順」を引ける対応表を作成
3. 章の構成と近傍ページを選ぶ
  - 親章のbrowse_tree(章ID)を呼び、章タイトルとページ一覧を取得
  - Graph候補ページの前後1ページを候補に加える(重複は除く)
  - 章内の全ページ本文を渡すのではなく、章の見出し・ページタイトル一覧は構成情報として使用
  - 本文はGraph候補と関連がありそうな近傍ページだけを渡す
4. 回答用の本文を組み立てる
  - Graph候補と採用した近傍ページについて、browse_tree(ページID)またはread_page(page_id)で全文を取得
  - Graphの経路とTree上の章・前後関係も一緒に渡す
    - モデルが「なぜこのページが追加されたか」を判断しやすくなる

# Question 2:

> モデルの口調や出力形式を変えたい場合と、新しい事実や頻繁に変わる情報を扱いたい場合では、ファインチューニングと外部データ参照をどう使い分けますか？理由も説明してください。

## Hybrid

```
[model] gemini-3.5-flash-lite
モデルの口調や出力形式を変えたい場合と、新しい事実や頻繁に変わる情報を扱いたい場合の使い分けについて、講義資料の考え方をもとに整理します。

### 1. モデルの口調や出力形式を変えたい場合
* **手段：ファインチューニング（FT）**
* **理由：**
  出力形式・口調・手順の守り方といった「振る舞い」は、小規模なファインチューニング（あるいは良質な手本データ）によって少量の学習で大きく変えることができるためです（第2回・PDF p.46）。事前学習済みのモデルに「どのような形式で答えてほしいか」という型を覚えさせることで、狙った振る舞いを安定させることができます（第2回・PDF p.23）。

### 2. 新しい事実や頻繁に変わる情報を扱いたい場合
* **手段：外部データ参照（検索・RAGなど）**
* **理由：**
  知識や新しい事実・最新の資料をファインチューニングでモデルに覚えさせるのは非効率であり、誤り（ハルシネーション）が増える傾向があることが研究等で報告されています（第2回・PDF p.46, p.47）。そのため、新しい知識の追加には検索（RAG）を活用する方が効果的です（第2回・PDF p.46, p.47）。また、モデル自体は学習データの時点（ナレッジカットオフ）までしか知らないため、最新の話題や頻繁に変わる情報は外部から資料として渡す必要があります（第2回・PDF p.22）。
```
